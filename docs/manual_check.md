# Независимая ручная проверка — план P3_isru_zbo, 2035 год, BASE

Расчёт вручную (калькулятор, без кода) против выгрузки движка для плана P3 в BASE. Те же ожидаемые значения 2035 года
проверяются автоматическим тестом; пересчёт любого выгруженного каталога только по
CSV (без импорта движка) — `python tests/independent_recalc.py <каталог результатов>`.

Входы: спрос 2035 = 100 т (критический 80); базовое хранилище: потери 4,5 %, хранение 0,72 млн/т-год; Earth-Core 6,2 млн/т,
резервирование 0,45; Earth-Flex 8,9, резервирование 0,15; 45-дневный резерв R = D × 45/365.

Хранение начисляется по тому же трапецеидальному правилу внутри горизонта и в подготовительном периоде:
средний запас месяца = (запас на начало + запас на конец)/2, стоимость = 0,72 × средний запас / 12.
Начальный запас хранится **с фактического месяца поставки**, а не бесплатно до 2035-01; расход
подготовительного периода относится на первый финансовый год (см. `configs/assumptions.yaml:
prep_period_holding_charged`). Перенос поставки начального запаса с 2034-12 на 2034-05 добавляет
семь месяцев хранения, 0,72 × 12,329 × 7/12 = 5,178 млн у.е., и эта разница видна в PV.

## Проверка пика внутри месяца (ёмкость хранилища)

Ёмкость проверяется не только на конец месяца. Месячный объём канала приходит N партиями
(`intra_month_delivery_batches`, принято N = 1), выдача равномерна; пик после партии j равен
`I_нач + (j × нетто − (j − 1) × выдача)/N`. Ручная проверка для 2035-01 плана P3:

| Шаг | Ручной расчёт | Ожидание | Движок | OK |
|---|---|---:|---:|:---:|
| Нетто-поступление 2035-01 | 109,876/12 × (1 − 0,045) | 8,744 т | 8,744 | ✓ |
| Выдача 2035-01 | 100/12 | 8,333 т | 8,333 | ✓ |
| Пик внутри месяца (N = 1) | 12,329 + 8,744 | 21,073 т | 21,073 | ✓ |
| Ёмкость базового хранилища | — | 70 т | 70 | ✓ |

Превышение пика — жёсткое нарушение `INTRA_MONTH_PEAK`. Запас по ёмкости во всех принятых планах
и чувствительность к N = 2, 4, 12 — `results/intra_month/intra_month_capacity.md`.

Граничные проверки (покрыты автоматическими тестами): пустой план → дефицит = весь спрос, запас 0, отрицательного запаса нет;
100 т, поставленные в хранилище на 70 т, → STORAGE_OVERFLOW 2035-01 с превышением 30+ т; Emergency > 20 % три года подряд →
EMERGENCY_BASE_STREAK; CAPEX 1 850 к 2037 → CAPEX_2037 с превышением 50; ISRU, оплаченный в 2038-03, → INVESTMENT_TIMING и
SOURCE_NOT_AVAILABLE; годовой объём, смещённый в один месяц, → INTRA_MONTH_PEAK (жёсткое).
Ошибочный ввод (также покрыт автоматическими тестами): отрицательный резерв, неизвестный источник, год вне горизонта,
критический спрос выше общего, отрицательный критический спрос, отрицательный срок поставки, отрицательный CAPEX,
нечисловое и бесконечное значение, сценарий без идентификатора, некорректный JSON — каждое сообщение называет файл,
строку, поле и значение; CLI возвращает код 3.
