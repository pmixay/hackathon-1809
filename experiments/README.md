# Эксперименты и воспроизводимые протоколы EXP-01–12

Каждый эксперимент — скрипт, повторный запуск которого обновляет свой каталог `results/`.
EXP-10 использует фиксированный seed и общие реализации; остальные эксперименты не используют
случайную выборку. Детерминированность относится к расчётам: стандартная оболочка экспорта содержит время генерации.

Общие входы: `data/case/` (CASE_INPUT), `configs/assumptions.yaml` (реальная ставка 8%,
максимальный срок поставки, лаг ZBO 0), движок `src/terraplan`, календарный месяц 2035–2040.
Собственные шоки — `TEAM_ASSUMPTION`; контрольные данные организатора не изменяются.
Полный запуск: `python experiments/run_all.py`.

### Существенные ограничения вывода

- P1 не обеспечивает спрос 2040. P3 дешевле в BASE, P2z — при адаптации к обязательному стрессу.
- P3 ×1,05 спроса и 0,95 доли ISRU — первые неуспешные точки EXP-04, не триггеры P2z.
  Перепланированный P3 ×1,25 проходит ограничения, но имеет дефицит 12,437 т; ×1,30 не проходит.
- В опыте лага ZBO 10 месяцев впервые нарушается **годовой потолок потерь**. Резерв/сервис
  исходного BASE P3 в стрессе нарушены уже при лаге 0; ввод до 2038 — консервативная цель.
- EXP-03 не моделирует сокращение заказов при замороженных контрактах: он пересматривает и резервирование.
  Нулевой TOP-простой неизменного плана не доказывает отсутствие цены будущего сокращения заказов.
- EXP-06: дефицит 0,866 т, минимальный сервис 0,996987; резерв января 2038 не исправлен.
  Разница с заблаговременной адаптацией 498,506 млн PV не равна цене информации: конечные запасы
  55,295 и 21,755 т различаются, в восстановлении есть ещё 33,947 т Emergency в 2040.
- Адаптированные P2z/P3/P4 в BASE дают 17/25/25 переполнений. Единой робастной политики не доказано.
  EXP-05 с синтетическим Source-X не заменяет расчёт восстановления после стресса в 2041.

## Переносимая проверка происхождения данных

```bash
python experiments/provenance.py
python experiments/provenance.py results/geopolitical_price_shock results/p2z_resilience
```

Схема отчёта/манифеста 2, формат `sha256-utf8-lf-v1`: декодирование UTF-8, замена CRLF/CR
на LF, кодирование UTF-8 и SHA-256. Пробелы, числа, порядок JSON и последний перевод строки
сохраняются: реальные правки обнаруживаются. Общий `provenance.py` входит в хеши входов.
Команда без аргументов проверяет EXP-07–10; EXP-11/12 передаются явно.

Хеши относятся к использованным при пересчёте входам и коду. EXP-09 дополнительно проверяет
копии CASE_INPUT; EXP-10/11/12 — переносимые выходные файлы. Проверки опубликованных данных
дополнены тестами LF/CRLF и обнаружением подмены. Числовая проверка `terraplan verify` использует
свои семантические хеши и допуски; побайтовое сравнение не заменяет её.

Повтор EXP-10 с `--compare` требует одинаковых записанных версий среды. Различия версий видны
в манифесте и могут потребовать числового сравнения; переносимость окончаний строк не обещает
идентичные байты между версиями Python. После изменения `run_all.py` выборка EXP-10 повторяется,
чтобы обновить происхождение данных реальным расчётом, а не переподписать старые результаты.

## EXP-07: обратный стресс адаптированного P3

```bash
python experiments/run_reverse_stress.py --max-shock 0.5 --tolerance 1e-12 --out results/reverse_stress
python -m pytest -q tests/test_reverse_stress.py
```

- **Цель/план:** граница отказа сохранённого `P3_isru_zbo_adapted.json`; заказы, резервы,
  начальный запас и инвестиции фиксированы.
- **Фон/факторы:** MANDATORY_STRESS. В 2038–2040 общий и критический спрос умножаются на `1+d`,
  доли ISRU на `1-s`: спрос `1,15*(1+d)`, ISRU `[0,55; 0,75; 1]*(1-s)`. Снижение относительное,
  не в процентных пунктах; ранние годы, цены, потолок потерь и другие источники прежние.
  Надёжность повторно не умножается.
- **Метрика:** инфимум `max(d,s)` по нарушающим точкам квадрата `[0; 0,5]²`. Равные веса
  относительных шоков и диапазон 50% — исследовательское допущение, не вероятности.
- **Отказ:** любое жёсткое нарушение либо годовой сервис <97%/99%; предупреждения не считаются.
  Допуск резерва 1e-6 т, сервиса 1e-9. Первое нарушение — по году/месяцу; годовое без месяца
  датируется декабрём, затем сортировка по правилу/источнику.
- **Алгоритм:** бисекция девяти нормированных лучей, включая оси и диагональ, до интервала
  радиуса ≤1e-12. Непроходящий ноль запрещён; если верхняя граница проходит, отказ в области не найден.
  Для фиксированного P3 шоки монотонно ухудшают запас/резерв при работающей ZBO: проходящая
  диагональ покрывает свой квадрат, нарушающая служит свидетелем. Это обоснование глобального
  инфимума в выбранной L∞-метрике, а не перебор каждого участка границы.
- **Артефакты:** `boundary.csv` с полной точностью и первым нарушением, `summary.md`,
  `report.json` со снимками, хешами, допусками, резервами, граничными сценариями/KPI.
  Это компактный CSV/JSON-отчёт без XLSX. Граница ≈0,0000551373% каждого шока отражает
  лишь около 0,47 кг запаса над резервом января 2040, а не практическую устойчивость.

## EXP-08: цена и остаточный риск защит P3

```bash
python experiments/run_protection_measures.py --target 0.01 --out results/protection_measures
python -m pytest -q tests/test_protection_measures.py
```

Фон и исходный план как в EXP-07. Минимум — наименьшая проверенная величина в заданном
семействе мер, проходящая исходный фон и целевой квадрат дополнительных шоков 1%.
Это `TEAM_ASSUMPTION`, не требование организатора/вероятность и не глобальный оптимум.
Каждый вариант далее фиксируется; используются критерий, 9 лучей, область 50% и допуск EXP-07.

| Мера | Реализация и поиск | Цена |
|---|---|---|
| Физический запас | Шаг 0,1 т нетто к январю 2038; Flex июль–декабрь 2037, заказы март–август (4 месяца); добавочный валовый месяц округляется вверх до 0,0001 т, годовой резерв покрывает месячный пик | Закупка + резервирование + хранение |
| Только резерв мощности | Диагностика +1 т/год, сначала свободная B, затем E в 2038–2040; отдельный контроль всего свободного объёма. A/D уже полностью зарезервированы | Только резервирование; B/E без TOP, физические поставки не добавляются |
| Ранний ZBO | Целые месяцы от 2037-07 назад до доступности 2036-01; исходные заказы сохраняются, сэкономленные потери остаются в запасе | Тот же номинальный CAPEX, более ранняя PV-оплата, OPEX и хранение |
| Ранний ZBO + запас | Выбранный ранний ZBO и отдельный поиск остаточного запаса с шагом 0,1 т | Сумма эффектов; отдельно от одиночной меры |

Потери применяются один раз к притоку, лаг ZBO остаётся 0. Простое резервирование не меняет
поставок при фиксированных заказах и не имеет достаточного защитного минимума; активация
требовала бы политики заказов и проверки сроков. Все меньшие уровни сохранены в `sizing.csv`.
`comparison.csv`, `boundary.csv`, отдельные `*.plan.json`, `report.json` содержат стоимость,
остаточные нарушения, годовые финансы/резерв и календарь. Цена — с мерой минус без меры на
одинаковом фоне, PV и номинал отдельно. Экономия закупки не приписывается сохранённому запасу.

## EXP-09: задержка подготовки Earth-New, риск R6

```bash
python experiments/run_earth_new_delay.py --out results/earth_new_delay
python -m pytest -q tests/test_earth_new_delay.py
python -m terraplan verify results/earth_new_delay/delay_03m --case results/earth_new_delay/delay_03m/case
python tests/independent_recalc.py results/earth_new_delay/delay_03m results/earth_new_delay/delay_03m/case
```

- **План/фон:** сохранённый P2z, спрос/цены BASE. Все даты оплаты, инвестиции, резервы,
  годовые заказы и исходные месячные слоты фиксированы; реакции нет.
- **Фактор:** только оба конца диапазона подготовки C увеличены на 0/3/6/12 месяцев на копии
  CASE_INPUT. При политике `max` ввод 2037-01 → 2037-04/2037-07/2038-01. Другие источники/ZBO прежние.
- **Договоры/календарь:** явные месячные слоты исключают автоматическое сжатие равномерного
  заказа в оставшиеся месяцы. Пропущенные слоты теряются без переноса, замещения и возврата;
  исходный объём оплачивается. Движок пропорционально доступности рассчитывает резервирование
  и выявляет нарушения. Это не очередь отложенных поставок.
- **Метрики:** дефицит и сервис, годовые запасы/45-дневный резерв/нехватка, затраты/дельты,
  пропущенные поставки, все нарушения и отдельно первое нарушение резерва. 100% сервиса не
  скрывает нарушение резерва/договора. Если год целиком недоступен, отчёт датирует годовую
  проверку C первым пропущенным слотом с пометкой; стандартный экспорт движка не меняется.
- **Выход:** сравнение, годовая таблица, сводка, детерминированный отчёт с хешами;
  каждый `delay_XXm/` содержит копию данных и стандартные CSV/JSON для повторного `verify`.
  Уменьшение расходов из-за потери топлива не является преимуществом риска.

## EXP-10: условный Монте-Карло защит P3

```bash
python experiments/run_monte_carlo.py --n 10000 --seed 203510 --out results/monte_carlo
python experiments/run_monte_carlo.py --n 10000 --seed 203510 --replay-samples results/monte_carlo/samples.csv --out results/monte_carlo_replay --compare results/monte_carlo
python -m pytest -q tests/test_monte_carlo.py
```

- **Планы:** фиксированный адаптированный P3, запас +8,6 т, ZBO с 2036-01 + запас 0,1 т;
  построители EXP-08. Фон — обязательный стресс, без дополнительного шока все три должны проходить.
- **Распределения:** постоянные по своим периодам `d ~ U(0; 0,02)` для обоих спросов и
  `s ~ U(0; 0,02)` для относительной недопоставки ISRU в 2038–2040; `p ~ U(−0,10; 0,10)`
  умножает уже стрессовые цены A/B на `1+p` в 2038–2039. Повторного учёта надёжности нет.
  Факторы независимы в основной модели, A/B имеют общий ценовой шок; параметры зарегистрированы
  в `configs/assumptions.yaml`. Диапазон 2% охватывает обе стороны защитной цели 1%; равномерность
  не утверждает наиболее вероятную величину без статистики, ценовой диапазон иллюстративный.
- **Зависимость:** отдельная диагностика использует один `u_demand` для `d` и `s`, цена независима;
  маргинальные распределения прежние. Результаты не смешиваются и не объявляются худшей вероятностной границей.
- **Выборка:** N=10 000 на модель, seed=203510, `random.Random`/MT19937; ровно три вызова
  `random()` на реализацию в порядке спрос/ISRU/цена. Диагностика не расходует новых случайных чисел.
  Все планы используют общую выборку: 60 000 случайных расчётов плюс три контроля. Малые N допустимы для тестов.
- **Отказ/метрики:** критерий EXP-07, все одновременные первые причины; число/частота отказов,
  95% интервал Уилсона (также для нуля/всех), отдельно резерв/сервис/дефицит, первые годы/месяцы,
  максимальная нехватка резерва, PV и попарные дельты. Для непрерывных величин среднее, min/max,
  P5/P50/P95 с интерполяцией `(N−1)*q` (тип 7); дефицит считается при >1e-6 т.
  Сохранены устранённые/новые нарушения и изменение в п.п., сравнение не является независимыми выборками.
- **Цена:** с мерой минус без меры в **той же** реализации; млн в ценах 2035, ставка 8%,
  правило начала года движка. Не оцениваются ущерб миссиям, штрафы, цена реактивных закупок или оптимальность.
- **Артефакты:** `samples.csv` с исходными равномерными числами и преобразованиями; `runs.csv`
  со всеми реализациями/планами и одновременными причинами; `comparison.csv`, `report.json`,
  `summary.md`, три плана. Манифест содержит seed/N, генератор/порядок, версии, снимки и хеши;
  без времени и локального пути. `--replay-samples` проверяет выборку против N/seed/допущений,
  `--compare` проверяет входы и все нормализованные артефакты при одинаковых версиях среды.
- **Ограничения:** это спрос + ISRU + цены, **не** случайные остановки мощности Core.
  Частоты условны, интервалы отражают ошибку выборки (до ≈0,98 п.п. половины ширины), не ошибку модели.
  Защита квадрата 1% не означает защиту квадрата 2%; ранний ZBO предполагает нулевой лаг и сохранение
  сэкономленного топлива. Никакого вероятностного ранжирования P2z/P3/P4 из EXP-10 не следует.

## EXP-11: отдельный геополитический ценовой шок

```bash
python experiments/run_geopolitical_price_shock.py
python experiments/run_geopolitical_price_shock.py --out results/geopolitical_price_shock_replay --compare results/geopolitical_price_shock
python experiments/provenance.py results/geopolitical_price_shock
python -m pytest -q tests/test_geopolitical_price_shock.py
python -m terraplan verify results/geopolitical_price_shock/P2z_earth_new_zbo/after --case results/geopolitical_price_shock/case
```

- **Цель/планы:** изолировать ценовую экспозицию фиксированных BASE P2z/P3/P4; шесть расчётов до/после.
  Стрессовые планы не подставляются, решение R2 не пересматривается автоматически.
- **Фактор:** переменные цены A/B ×1,25 в 2038–2039, возврат к BASE в 2040.
  Иллюстративное `TEAM_ASSUMPTION`, а не прогноз/вероятность. Для сопоставимости взят только
  ценовой компонент обязательного стресса: A 6,2→7,75, B 8,9→11,125 млн/т.
- **Копия данных:** `case/*.csv` — неизменённая копия CASE_INPUT, `shock.yaml` — снимок
  `team_geopolitical_price_shock.yaml`. Годовая накладка движка применяется один раз;
  `price_overlay.csv` раскрывает цены по источнику/году. Статическая цена CSV не перезаписывается,
  поскольку не кодирует двухлетнее окно. Агрегированная цена не разбивается на выдуманные компоненты.
- **Неизменно:** спрос, поставляемые доли, мощности, сроки/инвестиции, запас, заказы, резервирование,
  TOP, CAPEX/OPEX. Наценка применяется ко всему оплачиваемому объёму, включая возможный TOP.
- **Метрики:** затраты/PV и дельты, дефицит/сервис, запасы/резерв/нехватка по всем годам;
  отказ как в EXP-07. Дельты PV P2z/P3/P4: 470,891774 / 452,512590 / 415,516289 млн;
  итог 9 200,295536 / 9 091,369527 / 9 273,125433 млн. Сервис 100%, дефицит 0, резерв не нарушен;
  помесячный физический баланс идентичен. Меньшая прибавка P4 и меньший итог P3 — разные критерии.
- **Воспроизведение:** сравнение, годовые метрики, экспозиция цен, снимки, шесть стандартных
  CSV/JSON-выгрузок; нормализованные SHA-256. `result.json`/`run_manifest.json` с путями и
  `export_envelope.json` с временем исключены из побайтового сравнения; числа проверяет `verify --case`.
  Тесты проверяют неизменность входов, точную изоляцию фактора, независимую арифметику,
  физическую идентичность, повтор, подмену и опубликованные результаты.
- **Граница:** не моделируются перебои, задержки, лимиты платежей, реакция или смешанные шоки.
  Физическая неизменность в ценовом опыте не доказывает геополитическую устойчивость в целом.

### А. Меры против задержки

**Цель:** количественно закрыть цену меры/остаточный риск R6 для выбранного P2z, не переносить выводы P3.
Фон BASE, неизменные исходные решения P2z; задержка и оплата пропущенных слотов как в EXP-09,
копии данных +0/3/6/12 месяцев. Цель +3 месяца — первый ненулевой шаг EXP-09, не оценка вероятности.

1. **Физический запас:** добавить оплаченные Flex-поставки июля–декабря 2037, заказанные
   март–август с 4-месячным сроком, при действующей ZBO с лагом 0. Поиск 0,1 т нетто до
   предела свободной мощности Flex за полгода; месячный валовый объём вверх до 0,0001 т,
   резервирование до месячного пика ×12 (вверх до 0,001 т/год). Все меньшие уровни проверяются:
   монотонность полной исполнимости по запасу не предполагается из-за вместимости.
   Требования отбора: полный проход без задержки и физический проход при +3 мес.
   Минимум 3,2 т нетто; фактически из-за округления 3,2005272 т, валово 3,2394 т.
   Доплата 31,136158 млн PV. Исходные C-заказы/обязательства не отменяются:
   резерв восстановлен, но `SOURCE_NOT_AVAILABLE` и `ORDER_EXCEEDS_RESERVATION` остаются.
2. **Защитный календарь:** при реализации опциона в 2035-01 заранее принять C только
   на апрель–декабрь 2037. Сумма прежняя 13,1882 т, годовой резерв 17,585 вместо 13,189 т/год,
   прочие решения прежние. Один и тот же календарь проверяется при всех задержках: никакой
   адаптации с задним знанием события. Он полностью проходит 0/+3 месяца; доплата
   0,285425 млн PV без задержки и 6,712365 млн PV к исходному плану **при том же +3-мес. шоке**.
   При +6/+12 месяцах не проходит, нехватка резерва 4,125382/12,812010 т.

**Метрики/ограничения:** 12 стандартных расчётов, сравнение PV/номинала, отдельная дельта
к исходному BASE, годовые запасы/сервис, все нарушения и компоненты цены. Физический проход
проверяет резерв/хранилище/сервис/потери и не подменяет полный критерий. Цена штрафов/миссий,
договорная согласуемость и онлайн-реакция не моделируются. Меры не ранжируются по вероятностям
и не объявляются глобально оптимальными. Их проверка в BASE не доказывает защиту в обязательном стрессе.

### Б. Чувствительность и обратный стресс

**Планы/фон:** исходный P2z и две меры на BASE; отдельно сохранённый адаптированный P2z
на MANDATORY_STRESS. Ввод без задержки, все решения каждого плана фиксированы.
В 2038–2040 дополнительный общий/критический спрос `1+d` и относительная фактическая поставка
**C** `1-c`; исходные ISRU-множители стресса сохраняются, но ISRU в P2z нет.
Цены A/B отдельно ×0,8/1/1,25/1,5 в 2038–2039 поверх цен фона. Эти факторы не заменяют задержку ввода.

Сетка физических факторов по одному: 0/1/2/5/10%. Обратный стресс: 9 лучей, метрика `max(d,c)`,
квадрат до 50%, бисекция до 1e-10 абсолютной доли; допуски движка как EXP-07.
Это исследовательские диапазоны, не прогноз/управленческий триггер. На фиксированных планах с ZBO
монотонное снижение запасов и рост требований обосновывают проверку квадрата по диагонали.
Сохраняются обе стороны границы, первые нарушения и KPI. Независимый тест выводит границу
из начального запаса, накопленных спроса/нетто-поставок C и требования резерва.

На диагонали первое нарушение — резерв января 2040. Исходный BASE ≈0,00004129% каждого шока,
адаптированный стресс ≈0,00004963%; запас BASE ≈0,3915755%, календарь BASE ≈0,00891482%.
Календарь решает конкретную задержку, а не существенную недопоставку после ввода.
Случайных распределений, seed и Монте-Карло в EXP-12 нет: выбран проверяемый обратный стресс.

### В. Артефакты и реестр допущений

выгрузок и `cases/`. Манифест хеширует входы и переносимые выходы, включая копии данных.

## MCDA роли 2: итоговый выбор стратегии

```bash

```

Жёсткий фильтр: исполнимы BASE и адаптированный MANDATORY_STRESS; P1/P2 исключаются до
